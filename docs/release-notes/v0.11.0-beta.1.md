# YouTube Local Archiver — v0.11.0-beta.1

A self-hosted archiver for **your own** YouTube data — liked videos, watch
history, playlists, channels — built on **yt-dlp + FastAPI + RQ + PostgreSQL**
with a React admin console. It runs on your own machine, storing metadata and
(optionally) media bodies, and keeps them browsable, searchable, and backed up.

**This is the first public beta.** It is designed for **local, single-user**
use. It is **not** a hosted, multi-tenant, or production-hardened service.

## Highlights

- **Archive** liked videos / watch history imported from Google Takeout, plus
  arbitrary video / playlist / channel URLs. Metadata first (info.json,
  description, thumbnails, subtitles, comments, live chat), with a separate,
  explicit step to download the actual media body.
- **Browse, search & play**: filter/sort/search across titles, channels,
  comments and live chat; in-browser playback with HTTP Range seeking.
- **Jobs & scheduler**: queued downloads/refreshes with retry classification and
  a manual "run once" scheduler — no unattended bulk downloads by default.
- **First-run checklist** guides setup on a fresh install (nothing auto-runs).
- **Runtime vs. last-scanned-release** are shown separately, so a stale release
  scan is never presented as the running build's.
- **Operations**: backup / restore rehearsal, an append-only audit trail, and a
  read-only System panel.
- **Secure by default**: the admin console binds to `127.0.0.1` out of the box.
- **Isolated synthetic demo** (`docs/demo/`) for evaluating the UI without any
  real data.

## Install (Docker Compose)

```bash
git clone https://github.com/O-G-F/YouTube_Archiver.git youtube-archiver
cd youtube-archiver
cp .env.example .env      # then edit: storage paths + a strong Postgres password
docker compose up -d --build
```

Open <http://127.0.0.1:8000>. For LAN access set `WEB_BIND_HOST=0.0.0.0` in
`.env` **and enable authentication first** (see the README "Security posture").

## Update & rollback

```bash
./scripts/backup.sh        # always back up first
git pull && docker compose up -d --build
```

Roll back by checking out the previous commit and rebuilding — safe when the
`schema_head` is unchanged (`archiver system version`). If a future release
carries an incompatible migration, roll back by **restoring the backup** rather
than downgrading the database.

## Security posture — please read

- The image ships **7 known CRITICAL OS-package CVEs** that have **no upstream
  fix** yet. They are **not hidden** — the System panel surfaces them and each is
  analysed in the decision dossier.
- **This build is not production-ready.** The release-check intentionally
  **FAILs** on those CVEs and on **unverified scanner provenance**; that FAIL is
  by design and is not overridden, and there are **0 active vulnerability
  exceptions**.
- **Do not expose it anonymously to the internet.** Keep it on loopback / a
  trusted host, or put it behind authentication + a trusted reverse proxy.

## Known limitations

- Local single-user only; no multi-user roles or hosted-service hardening.
- Downloading media bodies is rate-limited by YouTube; the tool throttles and
  retries but large archives take time and disk.
- Not production-ready (see above).
